# Обновления и запуск сервера — VitalyaClicker

Коротко: релизы игры лежат в GitHub-репозитории **`ArbyzikOwO/vitalyaclicker`**,
игра сама проверяет их и предлагает обновиться, а адрес игрового сервера
(туннель cloudflared) игра читает оттуда же.

---

## 1. Как это работает

```
   ┌──────────────────┐  «Выпуск обновления»   ┌────────────────────┐
   │ игра (владелец)  │ ──────────────────────► │ игровой сервер     │
   └──────────────────┘                         └─────────┬──────────┘
                                                          │ блокирует всех (sys.lock)
                        ┌─────────────────────────────────┴────────────────────┐
                        ▼                                                      ▼
        ┌──────────────────────────────┐                       ┌──────────────────────────────────┐
        │ этот компьютер               │                       │ облако GitHub                    │
        │ tools/release.js             │                       │ .github/workflows/release.yml    │
        │  1. поднимает версию         │                       │  1. тесты сервера                │
        │  2. prepare.js (стейдж)      │                       │  2. зависимости и Android SDK    │
        │  3. собирает EXE             │                       │  3. собирает EXE и APK           │
        │  4. собирает APK             │                       │  4. подпись APK ключом из секретов│
        │  5. GitHub Releases          │                       │  5. GitHub Releases              │
        └──────────────┬───────────────┘                       └────────────────┬─────────────────┘
                       └────────────────────────────────────────────────────────┘
                                          │
   ┌──────────────────┐   releases/latest │
   │ игра у игроков   │ ◄─────────────────┘
   │ (проверка 3 мин) │   скачивание → перезапуск / установка APK
   └──────────────────┘
```

1. Владелец жмёт **«🚀 Выпустить обновление»** в админке (или запускает
   `node tools/release.js` вручную, или запускает workflow в GitHub Actions).
2. Сервер рассылает всем `sys.lock` — у всех игроков появляется блокирующий
   экран с текущим шагом сборки.
3. Сборка идёт там, где выбрано: на этом компьютере (`tools/release.js`) или в
   облаке GitHub (`.github/workflows/release.yml`). EXE и APK попадают в
   GitHub Releases, `version.json` обновляется.
4. После успеха сервер снимает блокировку и рассылает `sys.update`.
5. Игра у каждого игрока читает `version.json` из репозитория (при запуске и
   раз в 3 минуты): если версия новее — **блокирует игру** и показывает окно
   обновления (без «позже» — см. раздел 5).
   GitHub API намеренно **не используется**: у анонимных запросов лимит
   60 в час на IP, а за одним адресом может быть много игроков. Версия и
   имена файлов лежат в обычном файле репозитория `version.json`, а сборка
   скачивается по постоянной ссылке `releases/latest/download/<имя файла>`.

## 2. Установленный адрес сервера

Адрес сервера **не зашит намертво**: при запуске игра берёт его из
`server.txt` репозитория (`https://raw.githubusercontent.com/ArbyzikOwO/vitalyaclicker/main/server.txt`).

* Файл обновляет скрипт запуска сервера (`tools/run-server.*`) — каждые 6 часов,
  когда перезапускается туннель cloudflared.
* Если игрок вручную указал адрес в ⚙️ («адрес сервера»), автоматический адрес
  больше не используется (`meta.manualServer`).
* Если файл недоступен, используется адрес, зашитый при сборке (fallback).

Зашитые при сборке значения (`_build/prepare.js`):

| Значение | Что это |
|---|---|
| `window.VC_SERVER` | адрес сервера по умолчанию (fallback) |
| `window.VC_REPO` | `ArbyzikOwO/vitalyaclicker` |
| `window.VC_VERSION` | версия игры из `version.json` |
| `window.VC_PLATFORM` | `win`, `android`, `linux` или `web` |

## 3. Запуск сервера с туннелем cloudflared

### Windows

```bat
tools\run-server.cmd
```

Опции: `tools\run-server.cmd -Port 3000 -RestartHours 6 -NoPublish -NoTunnel`

* запускает `node server/server.js`;
* поднимает `cloudflared tunnel --url http://127.0.0.1:3000`
  (если cloudflared нет — скачает сам в `tools\cloudflared.exe`);
* вытаскивает публичный адрес и пишет его в `tools\server.txt`;
* публикует `server.txt` в GitHub (токен берётся из `tools\gh.config.json`,
  отключается флагом `-NoPublish`);
* каждые 6 часов перезапускает туннель (адрес меняется — файл обновляется).

### Linux

```bash
chmod +x tools/run-server.sh
tools/run-server.sh
```

Переменные окружения: `PORT`, `RESTART_HOURS`, `NOPUBLISH=1`, `NOTUNNEL=1`,
`CLOUDFLARED=/путь/к/cloudflared`, `GH_TOKEN`, `GITHUB_REPO`.

Автозапуск через systemd (`/etc/systemd/system/vitalyaclicker.service`):

```ini
[Unit]
Description=VitalyaClicker server + cloudflared tunnel
After=network-online.target

[Service]
WorkingDirectory=/opt/vitalyaclicker
ExecStart=/bin/bash /opt/vitalyaclicker/tools/run-server.sh
Restart=always
RestartSec=10

[Install]
WantedBy=multi-user.target
```

Логи: `tools/logs/server.log`, `tools/logs/cloudflared.err.log`.

> Cloudflared-fallback: обычный (`trycloudflare.com`) туннель бесплатный, но
> адрес каждый раз новый. Поэтому файл `server.txt` и нужен — игра подхватит
> новый адрес автоматически.

## 4. Выпуск обновления

### Из игры (обычный способ)

«Онлайн» → «Админ» → блок **🚀 Выпуск обновления** (виден только владельцу):

* поле версии можно оставить пустым — версия поднимется сама (1.0.6 → 1.0.7);
* поле «что нового» попадёт в описание релиза и в окно обновления у игроков;
* список **«Где собирать»**:
  * **авто** — на этом компьютере, если на нём есть всё для сборки, иначе в облаке GitHub;
  * **только этот компьютер** — локальная сборка (нужны `_build\jdk`, `_build\sdk`, установленные
    `node_modules` и ключ подписи);
  * **только GitHub (облако)** — сборка идёт в GitHub Actions: на машине сервера ничего собирать
    не нужно, достаточно доступа к репозиторию;
* кнопка **🚀 Выпустить** запускает сборку. Текущий шаг виден в строке состояния под кнопкой,
  у облачной сборки — вместе со ссылкой на запуск в Actions.

Что считается «набором для сборки» (режим **авто** проверяет это на машине сервера):
`_build\electron\node_modules`, `_build\mobile\node_modules`, JDK 17 (`_build\jdk`, `VC_JDK` или
`JAVA_HOME`), Android SDK (`_build\sdk`, `VC_SDK`, `ANDROID_SDK_ROOT`) и ключ подписи APK.
Если чего-то нет — сервер сам отправит сборку в облако.

### В облаке GitHub (на машине сервера ничего собирать не нужно)

Кнопка в игре сама отправляет `workflow_dispatch` в `.github/workflows/release.yml`.
Вручную: вкладка **Actions** → **Выпуск обновления** → **Run workflow**. Поля те же, что в админке,
плюс галочка **«Только собрать»** — сборка без публикации релиза (файлы останутся в артефактах
запуска, удобно для проверки).

Workflow: `windows-latest`, Node 22, JDK 17, Android SDK 34 → прогон `server/test.js` → запись ключа
подписи из секретов → `node tools/release.js` → файлы в артефактах и в релизе.

Секреты репозитория (Settings → Secrets and variables → Actions):

| Секрет | Значение |
|---|---|
| `ANDROID_KEYSTORE_B64` | `vitalyaclicker.keystore` в base64 |
| `ANDROID_KS_PASS` | пароль хранилища и ключа |
| `ANDROID_KS_ALIAS` | alias ключа (`vitalyaclicker`) |

Ключ подписи в репозиторий не попадает (`*.keystore` в `.gitignore`) — он кладётся в секреты один раз,
поэтому подпись APK одна и та же у локальной и облачной сборки, и обновления ставятся поверх.

### Вручную (из корня проекта)

```bat
node tools\release.js                  :: версия поднимется автоматически
node tools\release.js --version 1.1.0  :: конкретная версия
node tools\release.js --notes "Что нового: ..."
node tools\release.js --no-upload      :: только собрать, без публикации
node tools\release.js --upload-only    :: только выложить уже собранное из dist
node tools\release.js --skip-apk       :: только EXE
node tools\release.js --linux          :: Linux AppImage (запускать на Linux)
```

Актуальный адрес сервера берётся из `tools/server.txt`, а если файла нет — из `server.txt` в корне
репозитория (в облаке есть только он, поэтому перед облачной сборкой запустите сервер с туннелем:
адрес будет опубликован в репозиторий автоматически).

Что делает `release.js`:

1. поднимает версию в `version.json`, `_build/electron/package.json`,
   `_build/mobile/package.json`;
2. запускает `_build/prepare.js` (стейдж + зашитые значения; адрес сервера
   берётся из `tools/server.txt`, переменная `VC_SERVER` переопределяет);
3. собирает EXE (`electron-builder --win --publish never`, portable);
4. собирает и подписывает APK (`_build/build-apk.js`);
5. создаёт релиз `vX.Y.Z` в GitHub с файлами `VitalyaClicker.exe` и
   `VitalyaClicker.apk` (старый релиз с тем же тегом перезаписывается)
   и обновляет `version.json`.

Прогресс уходит в stdout строками `PROGRESS: ...`, сервер пересылает их
игрокам; `DONE: <версия>` — успех, `FAIL: <причина>` — ошибка.

### Linux-клиент (AppImage)

Electron не умеет собирать Linux-бинарник на Windows, поэтому AppImage
собирается на Linux-машине (та же, где живёт сервер):

```bash
cd _build/electron && npm install && cd ../..
node tools/release.js --linux --version 1.1.0
```

* файл всегда называется `VitalyaClicker.AppImage` (по этому имени клиенты
  Linux находят обновление в последнем релизе, как EXE и APK);
* `prepare.js` получает `VC_TARGET=linux` — в сборку зашивается
  `window.VC_PLATFORM = 'linux'`;
* на Windows/Linux собираются только свои файлы: на Windows — EXE и APK,
  на Linux — AppImage. В `version.json` пишутся только те файлы, которые
  реально попали в релиз, чтобы игрок другой платформы не получил ссылку
  на несуществующий файл (и не оказался заперт обязательным обновлением).

Если EXE и APK уже выпущены, а AppImage нужен позже — на Linux с **той же**
версией:

```bash
node tools/release.js --linux --upload-only --version 1.1.0
```

Файл добавляется в уже существующий релиз (EXE/APK при этом не удаляются),
а в `version.json` остаётся перечень всех трёх платформ.

## 5. Как обновляется игра у игроков

Проверка: игра читает `https://raw.githubusercontent.com/ArbyzikOwO/vitalyaclicker/<ветка>/version.json`
(с обходом кэша) и сравнивает `version` со своей. Если новее — снизу справа
появляется баннер **«🚀 Доступно обновление»** и окно с описанием («что нового»).

### Обновления обязательны

Скипнуть обновление нельзя — пока версия старая, игра заблокирована:

* окно обновления **без кнопок «Позже» и закрытия** — закрыть его или убрать баннер не получится;
* проверка идёт при запуске (через 4 секунды) и далее **каждые 3 минуты**, а заблокированный экран
  заново перерисовывается **каждые 20 секунд**, чтобы его нельзя было убрать через отладчик;
* сервер при входе в онлайн (**WS `auth`**) сверяет версию клиента со своей и отклоняет устаревшую
  (`needUpdate`, закрытие с кодом `4004`) — так «застрять» на старой версии не выйдет, даже если
  клиентская проверка не сработала;
* послабление только для браузера и локальной разработки: клиенты без зашитой версии (`VC_VERSION`)
  гейтом не блокируются.

Проверка версии — `cmpVersion`/`isVersion` в `server/release-plan.js`, клиентская часть — `updater.js`
(`CHECK_MS`, `FORCED`, `REL_URL`, `force()`, `lock()`), серверная — `currentVersion()` и проверка в `auth`.

| Платформа | Поведение |
|---|---|
| **EXE (Windows)** | Игра скачивает `releases/latest/download/VitalyaClicker.exe` и **сама перезапускается**. Замену делает маленький служебный `.cmd` в `%TEMP%`: он в цикле повторяет `copy`, пока файл занят запущенной игрой (копия не проходит, пока процесс жив — это и есть ожидание выхода), затем запускает новую версию и удаляет себя. Никаких `tasklist`/`timeout`/конвейеров — у процесса, запущенного из игры, может не быть консоли, и такие команды виснут. |
| **APK (Android)** | Открывается загрузка APK в системном браузере, Android предлагает установить (подпись та же, поэтому обновление ставится поверх). Если автоматическое открытие не сработало, в окне появляется кнопка **«⬇️ Скачать VitalyaClicker.apk»** (`target="_system"`) — по ней можно просто тапнуть. |
| **AppImage (Linux)** | Открывается загрузка `releases/latest/download/VitalyaClicker.AppImage` в браузере; в окне остаётся ссылка на файл и напоминание `chmod +x`. |
| **Браузер** | Открывается страница релиза `releases/latest`. |

Обязательное окно показывается только если в `version.json` этого релиза есть файл
для текущей платформы (`assets[PLATFORM]`). Если обновление собрали без вашей
платформы, игра не запирается: приходит только сообщение и баннер — иначе игрока
некуда было бы отправить за файлом.

Проверка происходит при запуске (через 4 секунды) и далее каждые 3 минуты, а
заблокированный экран обновления перерисовывается каждые 20 секунд.
После выпуска сервер дополнительно рассылает `sys.update`, и игра проверяет
версию сразу.

| `_build/electron/preload.js` | мост Electron ↔ страница для автообновления |

## 7. Ограничения и тонкости

* **Linux-бинарника нет** (по договорённости): скрипт сервера и автообновление
  рассчитаны на Linux, но сама сборка Linux не выпускается. Если она
  появится позже — достаточно добавить файл `.tar.gz` в релиз, `updater.js`
  уже умеет его выбирать.
* **Токен GitHub** лежит в `tools/gh.config.json`. Этот файл исключён через
  `.gitignore` — не коммитьте его и не выкладывайте.
* **Сборка EXE** не пройдёт, если запущен старый `VitalyaClicker.exe`
  из `dist` (файл занят) — закройте игру перед выпуском.
* **Node/npm не в PATH** — скрипты сами добавляют папку Node в PATH для сборки.
* `.cmd`-файлы больше нельзя запускать напрямую из Node 20+ — npm вызывается
  через `node npm-cli.js`.
* **APK на Android** требует подтверждения установки: полностью «молча»
  Android обновлять сторонние APK не позволяет.
* **Кэш GitHub**: `version.json` отдаётся через CDN и обновляется до ~5 минут.
  Игра добавляет к запросу метку времени, поэтому обычно видит свежую версию
  сразу, но в худшем случае обновление подхватится в течение 5 минут (или при
  следующей проверке через 3 минуты).
* **Обязательность обновления** включается с этой версии: клиенты, которые уже
  стоят у игроков (`1.0.6` и раньше), версию не сообщают и `VC_VERSION` не имеют —
  их серверный гейт пропускает, они обновятся обычным уведомлением. Блокировка
  без «позже» действует для всех сборок начиная с этой.
* **Установка EXE** — это скачивание ~100 МБ целиком: игра закрывается, файл
  подменяется, игра открывается заново. Прерывать этот момент не нужно, а если
  что-то пойдёт не так, старая версия останется на месте и запустится как обычно.
* **Облачная сборка** идёт 10–20 минут (первые запуски дольше: GitHub скачивает
  зависимости). Прогресс в игре — со ссылкой на запуск в Actions. Если сборка там
  упала, смотрите лог шага в Actions: локальная сборка может пройти, а в облаке не
  хватать чего-то из окружения.
* **Секреты GitHub** (`ANDROID_KEYSTORE_B64`, `ANDROID_KS_PASS`, `ANDROID_KS_ALIAS`)
  менять произвольно нельзя: с другим ключом APK не встанет поверх старого, игрокам
  придётся переустанавливать игру. Ключ подписи всегда тот же, что в
  `_build\mobile\vitalyaclicker.keystore`.
* **Промокод админки** в репозитории не лежит: он берётся из `server/secret.json`
  (шаблон — `server/secret.example.json`) или из переменной `ADMIN_CODE`.
